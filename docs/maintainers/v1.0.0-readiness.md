# v1.0.0 Readiness

This document tracks the validation work needed before intentionally signaling
`v1.0.0` for `octostate`.

Use it as the source of truth for the readiness branch and readiness PR. The
actual version bump, changelog update, tag, and GitHub Release should still be
created by `release-please` after the readiness PR lands on `main`.

## Goals

- prove that the renamed `octostate` CLI is stable across core user flows
- capture reproducible evidence for the release-readiness PR
- surface and fix defects before intentionally triggering the first stable
  release

## Rules Of Evidence

- Use a sandbox GitHub org and disposable repositories only.
- Prefer reproducible command logs and CI artifacts over screenshots.
- Use screenshots only as supporting evidence when they improve readability.
- Record exact commands, fixtures, expected results, and actual results.
- If validation finds a defect, fix it and rerun the affected checks before
  marking the scenario complete.

## Readiness Workflow

1. Create a dedicated readiness branch and draft PR linked to the tracking
   issue.
2. Fill in the environment summary before running live validations.
3. Work through the validation checklist below and attach evidence as you go.
4. Fix any defects on the readiness branch, then rerun the affected scenarios.
5. When every required scenario is green, convert the PR from draft to ready.
6. Merge the readiness PR with an intentional releasable and breaking
   Conventional Commit signal only when you are ready for `release-please` to
   open or update the `v1.0.0` release PR.

## Migration Guidance Draft

Use this guidance in the eventual `v1.0.0` release PR and release notes:

- Update Go imports from `github.com/orang-gaboets/repo-builder/...` to
  `github.com/orang-gaboets/octostate/...`.
- Update install commands from
  `go install github.com/orang-gaboets/repo-builder/cmd/repo-builder@latest`
  to `go install github.com/orang-gaboets/octostate/cmd/octostate@latest`.
- Update local build and run commands from `cmd/repo-builder` to
  `cmd/octostate`.
- Update CLI invocations from `repo-builder ...` to `octostate ...`.
- No compatibility alias for the old CLI name is currently planned.

## Exit Criteria

- Every required checklist item above is complete.
- Defects found during validation are fixed or moved to explicit follow-up
  issues with a conscious decision not to block the release.
- The readiness PR contains enough evidence for another maintainer to audit the
  release decision without rerunning every flow from scratch.
- The merge strategy and final PR title are chosen intentionally so
  `release-please` opens or updates the `v1.0.0` release PR only when you want
  it to.
