# v1.3.0 Compatibility and Migration Notes

## Minimum Go Version

Starting with v1.3.0, Octostate requires Go 1.26.9 or newer for installation
from source, embedding in another Go program, and repository development.
The module declares `go 1.26.9`, which also implies the `go1.26.9` toolchain,
to remediate standard-library vulnerabilities affecting the previous Go 1.25.13
toolchain. Go removes a redundant explicit toolchain directive when both
versions match.

Before upgrading from v1.2.0, update the Go installation used by developer
machines and CI to Go 1.26.9 or newer. Consumers embedding Octostate must also
allow their module's minimum Go version to rise to at least 1.26.9 when
updating the dependency. Environments using `GOTOOLCHAIN=local` must install a
compatible toolchain explicitly; automatic toolchain switching is disabled.

Users of prebuilt CLI archives do not need a Go installation. This toolchain
migration does not change Octostate's exported Go APIs, CLI flags, configuration
format, or command output.

## Reusable Configuration Review Workflow

The reusable configuration-review workflow now installs Go 1.26.9 and retains
`GOTOOLCHAIN=local`. Its workflow revision and the `octostate_version` input
are independent pins.

When selecting a v1.3.0 CLI commit or a commit requiring Go 1.26.9, also select
a trusted workflow revision containing this toolchain upgrade. An older
workflow revision that installs Go 1.25.13 cannot build that CLI and fails
during installation. The current workflow accepts only a reviewed, full
40-character lowercase commit SHA for `octostate_version`; it rejects release
tags, branch names, abbreviated SHAs, and `latest`. Resolve a release tag to
its commit and review that commit before pinning it. Older workflow revisions
may retain the earlier tag-or-SHA input contract; caller behavior depends on
the pinned workflow commit.

Canonical docs:
[Control-repository integration](../gitops/control-repo-integration.md).
