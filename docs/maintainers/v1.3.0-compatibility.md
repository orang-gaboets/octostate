# v1.3.0 Compatibility and Migration Notes

## Minimum Go Version

Starting with v1.3.0, Octostate requires Go 1.26.10 or newer for installation
from source, embedding in another Go program, and repository development.
The module declares `go 1.26.10`, which also implies the `go1.26.10` toolchain.
This patch-level minimum includes the standard-library fix for GO-2026-6809 in
`crypto/x509`. Go removes a redundant explicit toolchain directive when both
versions match.

Before upgrading from v1.2.0, update the Go installation used by developer
machines and CI to Go 1.26.10 or newer. Consumers embedding Octostate must also
allow their module's minimum Go version to rise to at least 1.26.10 when
updating the dependency. Environments using `GOTOOLCHAIN=local` must install a
compatible toolchain explicitly; automatic toolchain switching is disabled.

Users of prebuilt CLI archives do not need a Go installation. This toolchain
migration does not change Octostate's exported Go APIs, CLI flags, configuration
format, or command output.

Canonical docs: [Getting started](../getting-started.md),
[Go API and consumer guide](../go-api.md),
[Development](development.md).

## Reusable Configuration Review Workflow

The reusable configuration-review workflow now installs Go 1.26.10 and retains
`GOTOOLCHAIN=local`. Its workflow revision and the `octostate_version` input
are independent pins.

When selecting a v1.3.0 CLI release or a commit requiring Go 1.26.10, also select
a trusted workflow revision containing this toolchain upgrade. An older
workflow revision that installs a toolchain below Go 1.26.10 cannot build that
CLI and fails during installation. Pin the workflow to a reviewed immutable
commit and the CLI to a compatible release tag or full commit SHA; do not use a
branch name or `latest` for the CLI input.

Canonical docs:
[Control-repository integration](../gitops/control-repo-integration.md).
